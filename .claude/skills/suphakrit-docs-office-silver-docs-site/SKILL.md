# Office Silver Docs Site

สไตล์ของเว็บเอกสารใน `doc/site/` ถอดจากโค้ดจริง ไฟล์นี้บอกวิธีสร้างหน้าใหม่ให้ได้เอกลักษณ์เดียวกัน

## 1. Purpose

สร้าง **เว็บอ่านเอกสาร** (documentation reader) ที่รู้สึกเหมือนเอกสาร Office: พื้นสว่าง นิ่ง หนาแน่นพอดี ตัวอักษรใหญ่อ่านสบาย ตารางเป็นหัวใจ ไม่มีของตกแต่ง ใช้กับเนื้อหาไทยเป็นหลัก

**ขอบเขต:** เว็บอ่านเนื้อหายาว (คู่มือ สเปก บันทึกการตัดสินใจ ER/flow diagram) ไม่ครอบคลุม hero, form, footer, modal, tabs เพราะต้นฉบับ **ไม่มี** องค์ประกอบเหล่านี้ (ดู §6)

**ไฟล์ต้นฉบับที่เป็นหลักฐาน:** `doc/site/template.html` (CSS + JS ทั้งหมด), `doc/site/build.py` (ทะเบียนหน้า + ฝัง markdown), `doc/site/er_svg.py` (แผนภาพ ER วาดเอง), `doc/site/vendor/` (marked, mermaid) ไฟล์ `index.html` เป็นผลที่ build ออกมา อย่าแก้ตรง

## 2. Design Philosophy

เอกลักษณ์มาจากการตัดสินใจเหล่านี้ (ทุกข้อมีในโค้ด):

1. **กระดาษบนโต๊ะ:** พื้นหน้า `#eceef1` (เงินอ่อน) วาง "แผ่นกระดาษ" ขาว `#fff` มีเส้นขอบบาง 1px ไม่มีเงา ไม่มี gradient ในพื้นที่อ่าน (gradient มีเฉพาะแถบข้างซ้าย `#f4f5f7 → #e5e7eb`)
2. **สีเดียวสำหรับทางเลือก:** ใช้น้ำเงิน `#1f5fae` เป็นสีเน้นสีเดียว (ลิงก์ หน้าปัจจุบัน focus กรอบคำอธิบาย) ที่เหลือเป็นเฉดเทา
3. **โครงสร้างบอกด้วยเส้น ไม่ใช่กล่อง:** หัวข้อ h1 มีเส้นใต้หนา 2px, h2 เส้นใต้ 1px, แยกส่วนด้วย `hr` เส้นบาง การ์ดซ้อนการ์ดไม่มี
4. **ตารางคือหน่วยเนื้อหาหลัก:** ข้อมูลส่วนใหญ่แปลงเป็นตาราง (หัวสีเงิน แถวสลับสี คอลัมน์แรกตัวหนา) มากกว่าย่อหน้า
5. **อ่านสบายก่อนแน่น:** body 17px / line-height 1.8, ย่อหน้ากว้างไม่เกิน `75ch`, ระยะหัวข้อใหญ่ (h2 เว้นบน 2.4rem)
6. **ไดอะแกรมต้องอ่านได้จริง:** ไม่ย่อจนตัวอักษรจิ๋ว มีกรอบซูม/ลาก และ tooltip ข้อมูลเต็ม
7. **นิ่ง:** ไม่มี transition หรือ animation ในส่วนเนื้อหา ยกเว้น **skeleton loading** ที่เพิ่มภายหลังตามคำขอผู้ใช้ (แถบเทาวิบวับ 1.4 วินาที/รอบ ปิดอัตโนมัติเมื่อผู้ใช้ตั้ง `prefers-reduced-motion`) ใช้เฉพาะตอนรอโหลด ไม่ใช่การตกแต่ง

## 3. Design Tokens

ค่าทั้งหมดอยู่ใน `assets/office-silver.css` (สกัดจากต้นฉบับ ห้ามแต่งค่าใหม่เมื่อมีค่าที่ตรงบทบาท)

### สี

| Token | ค่า | บทบาท |
|---|---|---|
| `--page` | `#eceef1` | พื้นหลังหน้า |
| `--paper` | `#ffffff` | แผ่นเนื้อหา, ช่องค้นหา, ปุ่ม |
| `--silver` | `#e5e7eb` | หัวตาราง, แถบเครื่องมือไดอะแกรม, เส้นใต้ h1 |
| `--silver-2` | `#f3f4f6` | พื้น `code`, ปุ่ม pager |
| `--border` | `#cfd4db` | เส้นขอบทั่วไป |
| `--text` | `#1f2937` | ข้อความหลัก |
| `--text2` | `#4b5563` | ข้อความรอง (ต้นฉบับคอมเมนต์ว่า 7.5:1 บนขาว) |
| `--primary` | `#1f5fae` | ลิงก์, หน้าปัจจุบัน, focus, ขอบ callout |
| `--primary-bg` | `#e8f0fb` | พื้น hover, หน้าปัจจุบัน, callout |
| `--warn-bg` / `--warn-bd` | `#fff4e0` / `#f0b45a` | **ประกาศไว้แต่ไม่ได้ใช้** ในต้นฉบับ |

### สีสถานะในเนื้อหา
ต้นฉบับไม่มีสี success/error ใน CSS ใช้ **emoji ในข้อความ markdown** แทน: ✅ ผ่าน/ตัดสินใจแล้ว · 🔴 BLOCKER · 🟠 WARNING · ⚠ คำเตือน ถ้าต้องการสีสถานะจริง ให้ยืมจากแอป (`--success #166534`, `--warning #92400e`, `--error #b42318` ใน `frontend/src/styles/tokens.css`) และถือว่าเป็นส่วนเพิ่ม

**ข้อควรระวัง:** ต้นฉบับ **ไม่ได้โหลดฟอนต์** (ไม่มี `@font-face` หรือ Google Fonts) อาศัยฟอนต์ที่ติดตั้งในเครื่อง ถ้าเครื่องไม่มี Sarabun/Noto Sans Thai จะตกไป `system-ui` ถ้าต้องการให้เหมือนกันทุกเครื่อง ให้เพิ่มการโหลดฟอนต์เป็นงานเสริมและแจ้งผู้ใช้

### ระยะและรูปทรง

- มุมโค้ง: **4px** (ปุ่ม input ตาราง รูป pager `pre`), **6px** (แผ่นกระดาษ tooltip), 3px (`code`)
- เส้นขอบ: 1px เสมอ (ยกเว้น h1 2px, ขอบซ้ายหน้าปัจจุบัน 3px, ขอบซ้าย callout 4px)
- ช่องไฟ: ตาราง `8px 12px` · แผ่นกระดาษ `32px 48px 40px` · แถบซ้าย `16px 12px` · ปุ่ม pager `8px 14px` · ช่องว่างระหว่างคอลัมน์ `24px`
- ระยะแนวตั้ง: h2 เว้นบน `2.4rem` ล่าง `.8rem` · h3 `1.8rem/.5rem` · `hr` `2rem` · ตารางและ `pre` `1.2rem` · ไดอะแกรม `1.4rem` · pager เว้นบน `2.5rem`

## 4. Layout Guidelines

โครงหน้า 3 ส่วน (CSS grid):

```
body: grid 276px | minmax(0,1fr)
├─ nav.side        sticky, สูงเต็มจอ, เลื่อนในตัว, พื้นไล่เฉด, เส้นขอบขวา
└─ .wrap           grid minmax(0,1fr) | 220px, gap 24px, padding 24px 28px 80px, max-width 1280px
   ├─ article      แผ่นกระดาษขาว ขอบ 1px โค้ง 6px
   └─ aside.outline sticky top 16px  (สารบัญหัวข้อในหน้า)
```

- **เนื้อหาเรียงจากบนลงล่างเป็นคอลัมน์เดียว** ในแผ่นกระดาษ ไม่แตกกริดหลายคอลัมน์ในเนื้อหา
- ลำดับเนื้อหาในหน้า: `h1` → ย่อหน้านำ → (ตารางสรุป) → `h2` ตามหัวข้อ → pager ท้ายหน้า
- ใช้ `min-width:0` / `minmax(0,1fr)` เสมอเพื่อไม่ให้ตารางหรือ `pre` ดันหน้ากว้างเกิน
- สารบัญขวาแสดงเมื่อมีหัวข้อ h2+h3 **มากกว่า 2 อัน** (ไม่เช่นนั้นเว้นว่าง)

## 5. Component Guidelines

เฉพาะที่มีจริงในต้นฉบับ:

| Component | หน้าที่ | วิธีสร้าง (ย่อ) |
|---|---|---|
| **แถบสารบัญซ้าย** | นำทางทุกหน้า | ชื่อเว็บ (h1) → ช่องค้นหา (สูง 36px) → หัวกลุ่ม (h2 เล็ก) → ลิงก์ หน้าปัจจุบัน = พื้นขาว + ขอบซ้าย 3px primary + ตัวหนา + ตัวอักษร primary |
| **เนื้อหา (article)** | แสดง markdown | แผ่นขาว; `a` สี primary มีเส้นใต้; `strong` น้ำหนัก 600 |
| **สารบัญในหน้า** | กระโดดหัวข้อ | ลิงก์ซ้อนเส้นซ้าย 2px สีเทา; hover = primary; ระดับ h3 เยื้อง 22px |
| **ตาราง** | เนื้อหาหลัก | ห่อด้วย `.tbl` (ขอบ 1px โค้ง 4px เลื่อนแนวนอนได้) · หัว `--silver` ตรึงบน · แถวคู่ `#f8f9fb` · คอลัมน์แรกตัวหนา · แถวสุดท้ายไม่มีเส้นล่าง · ตารางหัวว่าง (ตารางคู่ ชื่อ-ค่า) ซ่อนแถวหัว |
| **Callout** | ข้อควรรู้/การตัดสินใจ | `blockquote`: พื้น `--primary-bg` ขอบซ้าย 4px primary มุมขวาโค้ง |
| **โค้ด** | โค้ดแทรก/บล็อก | `code` ขอบบาง พื้น `--silver-2`; `pre` พื้น `#f6f7f9` ขอบ `--border` เลื่อนได้ |
| **รูป** | ภาพประกอบ | `max-width:100%` ขอบ 1px โค้ง 4px พื้นขาว |
| **Pager** | หน้าก่อน/ถัดไป | ปุ่มลิงก์สองฝั่งท้ายหน้า พื้น `--silver-2` ขอบ `--border`; hover = `--primary-bg` + ขอบ primary |
| **กรอบไดอะแกรม (.dg)** | ดูแผนภาพใหญ่ | แถบเครื่องมือ `--silver` (− % + พอดีกรอบ 100% เต็มหน้าจอ + คำใบ้) + พื้นที่ดูสูง `min(460px,70vh)` ดูรายละเอียดใน `references/diagram-and-tooltip.md` |
| **Tooltip** | ข้อมูลเต็มของไดอะแกรม | กล่องขาว ขอบ `#9ca3af` โค้ง 6px เงาเดียวในทั้งเว็บ ตามเมาส์ พลิกเมื่อชนขอบจอ |

| **Skeleton loading** | แทนที่เนื้อหาขณะโหลด | แท่ง `.sk` สีเงินวิบวับ วางใน HTML ตั้งต้น แทนที่ทั้งก้อนเมื่อข้อมูลพร้อม ดู §5.1 |

### 5.1 Skeleton loading (ส่วนเสริม ไม่มีในต้นฉบับรุ่นแรก)

CSS อยู่ใน `assets/office-silver.css` ส่วน `/* Skeleton loading */` (มาจาก `doc/site/template.html` รุ่นปัจจุบัน)

**ใช้เมื่อ:** ต้องรอจริง เช่น JS render markdown/สารบัญตอนเปิดหน้า, Mermaid render ไดอะแกรม (async, ช้าที่สุดในหน้า), เนื้อหาที่ fetch มา **ไม่ใช้** เมื่อเนื้อหาพร้อมทันที (เช่น เปลี่ยนหน้าด้วย hash จาก JSON ที่ฝังไว้แล้ว) เพราะจะกะพริบเปล่า ๆ

**รูปทรงต้องเลียนโครงจริง** ไม่ใช่แท่งเท่ากันหมด เพื่อไม่ให้หน้ากระโดดเมื่อโหลดเสร็จ:

| Class | เลียน | ขนาด |
|---|---|---|
| `.sk-h1` | หัวข้อ h1 | สูง 34px กว้าง 55% |
| `.sk-h2` | หัวข้อ h2 | สูง 24px กว้าง 35% เว้นบน 34px |
| `.sk-line` | บรรทัดย่อหน้า | สูง 14px (+ `.w90 .w85 .w75 .w60` ให้ความยาวต่างกัน บรรทัดสุดท้ายสั้นสุด) |
| `.sk-table` | ตาราง | สูง 150px |
| `.sk-diagram` | ไดอะแกรม | สูง 260px |
| `.sk-nav` / `.sk-link` | หัวกลุ่ม / ลิงก์ในแถบซ้าย | 12px กว้าง 45% / 16px กว้าง 78% |
| `.sk-out` | ลิงก์สารบัญขวา | 12px กว้าง 80% |

ทุกแท่งใส่ `class="sk sk-…"` คู่กัน (`.sk` = สีและ shimmer, `.sk-…` = ขนาด)

**สี/การเคลื่อนไหว:** ไล่เฉด `--silver → --silver-2 → --silver` เท่านั้น (ห้ามใช้ primary หรือสีอื่น) มุม 4px shimmer `1.4s ease infinite` และ `@media (prefers-reduced-motion:reduce)` ปิด animation เหลือแท่งเงินนิ่ง

**ไดอะแกรม Mermaid ไม่ต้องใส่แท่งเอง:** CSS จับ `.mermaid:not([data-processed])` ให้เป็น skeleton สูง 260px อัตโนมัติ (ซ่อนข้อความต้นฉบับด้วย `font-size:0`) เมื่อ Mermaid render เสร็จจะใส่ `data-processed` ให้เอง ถ้า render ล้ม ให้เพิ่ม class `.sk-fail` → หยุด shimmer แล้วแสดงโค้ดต้นฉบับเป็นตัวอักษร monospace (ผู้ใช้ยังอ่านได้ ไม่ค้างเป็นแท่งวิบวับตลอดไป)

**รูปแบบ HTML + การถอด (ตามต้นฉบับ):**

```html
<article id="out" aria-busy="true"><div role="status"><span class="sr">กำลังโหลดเนื้อหา</span>
  <div class="sk sk-h1"></div><div class="sk sk-line w90"></div><div class="sk sk-line w75"></div>
  <div class="sk sk-h2"></div><div class="sk sk-table"></div>
</div></article>
```

```js
out.innerHTML = marked.parse(md);   // แทนที่ skeleton ทั้งก้อนครั้งเดียว ไม่ลบทีละแท่ง
out.removeAttribute('aria-busy');
try { await mermaid.run({ nodes: out.querySelectorAll('.mermaid') }); }
catch (e) { out.querySelectorAll('.mermaid:not([data-processed])').forEach(n => n.classList.add('sk-fail')); }
```

**Accessibility:** กล่องที่กำลังโหลดมี `aria-busy="true"` และข้อความซ่อน `.sr` ("กำลังโหลด…") ใน `role="status"` ให้โปรแกรมอ่านหน้าจอรู้ แท่ง `.sk` เป็น div เปล่า (ไม่มีข้อความ ไม่รับ focus) เมื่อเสร็จต้องถอด `aria-busy` (และ `role` ถ้าใส่ที่กล่องหลัก) ทุกครั้ง

**ใช้ซ้ำหรือเฉพาะหน้า:** ทุกอย่างข้างบนเป็นองค์ประกอบกลางที่หน้าใหม่ใช้ได้เลย สิ่งเฉพาะหน้าที่ควรทำเป็นของตัวเอง: แผนภาพที่วางผังเอง (เช่น `er_svg.py`)

**องค์ประกอบที่ต้นฉบับไม่มี:** top navbar, hero, card grid, ปุ่ม primary/secondary แบบกว้าง, form, validation, footer, modal, dropdown, tabs ห้ามอ้างว่า "เป็นสไตล์ต้นฉบับ" ถ้าหน้าใหม่ต้องใช้ ให้สร้างจาก tokens ข้างบน (เส้น 1px, มุม 4px, เทา + primary เดียว, ไม่มีเงา/animation) และแจ้งว่าเป็นส่วนต่อยอด

## 6. Interaction Guidelines

**สถานะที่มีจริง:**

| องค์ประกอบ | hover | active/ปัจจุบัน | focus |
|---|---|---|---|
| ลิงก์แถบซ้าย | พื้นขาว | `aria-current`: พื้นขาว + ขอบซ้าย primary + ตัวหนา | outline 2px primary offset 2px (`:focus-visible`) |
| ลิงก์สารบัญขวา | สี primary + ขอบซ้าย primary | — | เหมือนกัน |
| ปุ่มในกรอบไดอะแกรม | พื้น `--primary-bg` | — | เหมือนกัน |
| ปุ่ม pager | พื้น `--primary-bg` + ขอบ primary | — | เหมือนกัน |
| ส่วนที่มี tooltip | เคอร์เซอร์ `help` | — | — |
| ช่องค้นหา | — | — | outline 2px primary |

- **ไม่มี** transition/animation ใด ๆ ยกเว้น skeleton loading (ดู §2 ข้อ 7) และไม่มี disabled state
- **Skeleton loading:** มี HTML โครงเทา (สารบัญ ชื่อเรื่อง ย่อหน้า ตาราง ไดอะแกรม) อยู่ในไฟล์ตั้งแต่ต้น แสดงก่อน JS ทำงาน แล้ว JS แทนที่ด้วยเนื้อหาจริง; แผนภาพ Mermaid ที่ยังไม่ render แสดงเป็นกล่องเทาวิบวับ (`.mermaid:not([data-processed])`); ไลบรารี Mermaid (3.5 MB) โหลดตอนหน้านั้นต้องใช้เท่านั้น; ใส่ `aria-busy` + ข้อความ `.sr` "กำลังโหลด…" สำหรับโปรแกรมอ่านหน้าจอ
- **นำทาง:** hash routing (`#id`) เปลี่ยนเนื้อหาในหน้าเดียว เลื่อนไปบนสุดทุกครั้ง; ลิงก์หัวข้อในหน้า (`#id~n`) เลื่อนไปหัวข้อ ไม่โหลดหน้าใหม่
- **ค้นหา:** กรองรายการในสารบัญตามชื่อและเนื้อหา (ไม่สนตัวพิมพ์)
- **ไดอะแกรม:** ลากเมาส์ = เลื่อน · Ctrl+ลูกกลิ้ง = ซูม (0.08–3×) · Shift+ลูกกลิ้ง = เลื่อนซ้าย-ขวา · ลูกกลิ้งปกติ = เลื่อนหน้าเอกสาร (ไม่ติดในกรอบ)
- **ข้อจำกัดที่ตรวจพบ:** ซูม/เลื่อนไดอะแกรมทำได้ด้วยเมาส์/ปุ่มเท่านั้น ไม่มีคีย์ลัด ถ้าสร้างใหม่ ควรเพิ่มคีย์บอร์ด (ส่วนเสนอแนะ ไม่ใช่ของเดิม)

## 7. Responsive Guidelines

breakpoint ที่มีจริง 3 จุด (ใช้ `max-width` ตายตัว ไม่ใช่ mobile-first):

| เงื่อนไข | เปลี่ยนอะไร |
|---|---|
| `≤ 1180px` | ซ่อนสารบัญขวา เหลือเนื้อหาคอลัมน์เดียว |
| `≤ 800px` | แถบซ้ายเป็นบล็อกบนสุด (`position:static`, สูงไม่เกิน 45vh) หน้าเป็นคอลัมน์เดียว padding 12px, แผ่นกระดาษ padding `20px 18px` |
| `print` | ซ่อนแถบซ้าย/สารบัญ/pager/แถบเครื่องมือไดอะแกรม พื้นขาว ไม่มีกรอบแผ่นกระดาษ ไดอะแกรมไม่ตัด |

ตารางเลื่อนแนวนอนในกรอบของตัวเอง ไม่ดันหน้า

## 8. Implementation Guidelines

**วิธีที่ต้นฉบับใช้ (stack ที่ตรวจพบ):**
- HTML ไฟล์เดียวต่อเว็บ + CSS ใน `<style>` + JS ใน `<script>` ไม่มี bundler/Node
- เนื้อหาเขียนเป็น **markdown** ฝังเป็น JSON ในหน้าตอน build (`build.py` อ่านไฟล์ → ใส่ใน `template.html` ที่จุด `__DATA__`) แล้ว render ฝั่งเบราว์เซอร์ด้วย `marked` (ฝัง `marked.min.js` ในโฟลเดอร์ `vendor/`, ใช้ได้ออฟไลน์)
- ไดอะแกรมสองแบบ: Mermaid (`mermaid.min.js` ในเครื่อง, `theme:'base'` ปรับสี) สำหรับ flow/state/sequence และ SVG วางผังเอง (`er_svg.py`) สำหรับ ER
- ทะเบียนหน้าอยู่ใน `PAGES` ของ `build.py`: `(กลุ่ม, id, ชื่อ, path, ชนิด)`

**การตั้งชื่อ/จัดโค้ด:** class สั้นพยางค์เดียว/ตัวย่อ (`.wrap` `.tbl` `.dg` `.tip` `.pager` `.outline`), ใช้ CSS variables เฉพาะสี, ค่าตัวเลขอื่นเขียนตรง, คอมเมนต์ภาษาไทยหัวแต่ละส่วนของ CSS, ไม่มี utility class

**เมื่อ stack ของโปรเจกต์เป้าหมายต่างออกไป** (React, Vue, SSG, Tailwind ฯลฯ): ถ่ายทอด **tokens + โครง 3 ส่วน + กติกาตาราง/หัวข้อ** ไม่ต้องเปลี่ยน stack เดิม เช่น ใน Tailwind ให้แมป tokens ไปที่ `theme.extend.colors` และใช้ค่าเดียวกัน

**ความปลอดภัย:** ต้นฉบับ render markdown ผ่าน `innerHTML` และตั้ง `securityLevel:'loose'` ของ Mermaid จึงเหมาะกับเนื้อหาภายในที่เชื่อถือได้เท่านั้น ถ้าเนื้อหามาจากผู้ใช้ภายนอก ต้อง sanitize (เช่น DOMPurify) และตั้ง Mermaid ให้เข้มกว่านี้

## 9. Do and Don't

**Do**
- ใช้ tokens จาก `assets/office-silver.css` ก่อนคิดค่าใหม่
- แปลงข้อมูลเป็นตาราง (หัวสีเงิน คอลัมน์แรกตัวหนา) แทนรายการยาว
- ใช้ `blockquote` เป็น callout (ข้อควรรู้/การตัดสินใจ/คำเตือน)
- แยกส่วนด้วยเส้นบาง 1px และระยะห่างหัวข้อที่ใหญ่
- ให้ไดอะแกรมใหญ่มีซูม/ลาก/tooltip และเริ่มที่ขนาดอ่านได้
- ทำสถานะด้วยข้อความหรือไอคอนควบคู่สี (ต้นฉบับใช้ emoji + ข้อความ)

**Don't**
- ไม่ใส่ hero, การ์ดสถิติ, gradient ในพื้นที่เนื้อหา, เงาของกล่อง/การ์ด (เงามีที่เดียวคือ tooltip)
- ไม่ใช้สีตกแต่งนอกเหนือน้ำเงิน `#1f5fae` + เฉดเทา
- ไม่ใส่ animation/transition โดยอ้างว่าเป็นสไตล์เดิม (shimmer ของ skeleton คือข้อยกเว้นเดียว)
- ไม่ใช้ spinner, skeleton สีอื่นนอกจากเงิน หรือ skeleton ที่รูปทรงไม่ตรงกับเนื้อหาจริง
- ไม่ปล่อย skeleton ค้างเมื่อโหลดล้ม (ใส่ `.sk-fail` หรือข้อความแจ้ง)
- ไม่ทำโหมดมืด (ต้นฉบับเป็นสว่างอย่างเดียว `<meta name="color-scheme" content="light">`) เว้นแต่ผู้ใช้สั่งและแจ้งว่าเป็นส่วนเพิ่ม
- ไม่ย่อไดอะแกรมจนตัวอักษรเล็กกว่าอ่านได้ (ต้นฉบับถอยจากการ "พอดีทั้งหมด" เพราะอ่านไม่ออก)
- ไม่ให้ย่อหน้ากว้างเกิน `75ch`
- ไม่ copy เนื้อหาเฉพาะของระบบตารางเรียน (ชื่อหน้า ข้อมูล ER) ไปเว็บใหม่
- ไม่ render เนื้อหาจากภายนอกผ่าน `innerHTML` โดยไม่ sanitize

## 10. Workflow

เมื่อได้รับงานสร้าง/ปรับเว็บเอกสารด้วย skill นี้:

1. **ดูโปรเจกต์เป้าหมาย:** stack, มีเนื้อหา markdown หรือไม่, ต้องออฟไลน์ไหม, ภาษา ถ้ามี design system อยู่แล้วให้ถามว่าจะใช้ skill นี้แทนหรือผสม
2. **จัดเนื้อหา:** แบ่งเป็นหน้า/กลุ่ม (กลุ่ม = หัวข้อแถบซ้าย) ตั้ง id สั้นต่อหน้า
3. **ตั้งฐาน:** คัดลอก `assets/office-silver.css` แล้วสร้างโครง `nav.side` + `.wrap > article + aside.outline` ตาม §4
4. **เขียนเนื้อหา:** ทำเป็น markdown ตามกติกา §5 (ตาราง callout หัวข้อ h1→h2→h3)
5. **ไดอะแกรม:** ใช้ Mermaid สำหรับ flow/state/sequence; แผนภาพ ER/ผังที่เส้นพันกันให้วางผังเอง อ่าน `references/diagram-and-tooltip.md`
6. **ตรวจโต้ตอบ:** คลิกสารบัญ ค้นหา ปุ่มซูม pager hash ลิงก์ข้ามหน้า และ skeleton (DevTools → Network: Slow 3G หรือ throttle CPU เพื่อเห็นช่วงโหลด; ลอง Mermaid ผิดไวยากรณ์เพื่อดู `.sk-fail`)
7. **ตรวจ responsive:** กว้าง 1500, 1100 (ซ่อนสารบัญขวา), 700 (แถบซ้ายขึ้นบน) และพิมพ์
8. **เทียบกับ §11** แล้วแก้ที่หลุด

ห้ามสร้างจาก template เอกสารทั่วไป (Docusaurus/GitBook ธีมเริ่มต้น) แล้วเปลี่ยนแค่สี ต้องมีโครง 3 ส่วน กฎตาราง/หัวข้อ และกฎไดอะแกรมตามนี้จริง

- [ ] แถบซ้าย sticky เต็มสูง มีช่องค้นหา หน้าปัจจุบันมี `aria-current` และขอบซ้าย 3px

- [ ] ไม่มี transition/animation/เงา (ยกเว้น tooltip และ shimmer ของ skeleton) ที่ผู้ใช้ไม่ได้ขอ

- [ ] ไม่มีเนื้อหาเฉพาะจากต้นฉบับค้างอยู่ (ชื่อ ข้อมูลระบบตารางเรียน)
- [ ] ทุกอย่างที่เพิ่มนอกเหนือต้นฉบับ (สีสถานะ, โหมดมืด, ฟอนต์โหลดเอง ฯลฯ) ถูกแจ้งว่าเป็นส่วนต่อยอด

## ที่ตรวจสอบไม่ได้ / ไม่ชัดเจน

- **ฟอนต์ที่แสดงจริง:** CSS ระบุ Sarabun/Noto Sans Thai แต่ไม่ได้โหลดให้ จึงไม่ทราบว่าเครื่องผู้ใช้เห็นฟอนต์ไหน
- ตรวจหน้าตาจริงด้วย Chromium (Playwright) ที่ความกว้างราว 1500px เท่านั้น **ยังไม่ได้ดูจริง** ที่ ≤800px และโหมดพิมพ์ (ข้อมูลส่วนนั้นมาจากการอ่านโค้ด)
- `--warn-bg/--warn-bd` ประกาศไว้โดยไม่มีที่ใช้ ไม่ทราบเจตนา
- เบราว์เซอร์อื่นนอกจาก Chromium: ใช้ `:has()` (ซ่อนหัวตารางว่าง) ซึ่งเบราว์เซอร์เก่าไม่รองรับ
