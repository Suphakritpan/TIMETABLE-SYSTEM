## 3. ขอ endpoint และพฤติกรรมเพิ่ม

1. **หน้าตารางสาธารณะ** ([adr/0001](adr/0001-public-read-only-timetable.md)): เส้นอ่านอย่างเดียว ไม่ต้องล็อกอิน คืนเฉพาะเวอร์ชัน `published` ของทุกภาควิชา ในมุมมองกลุ่มเรียน (ภาควิชา → กลุ่ม → ตาราง) ฟิลด์ที่ส่งได้: วิชา ชื่ออาจารย์ ห้อง วัน คาบ ห้ามส่ง อีเมล เวลาไม่ว่าง ความเห็น ร่าง หรือเวอร์ชันระหว่างตรวจทาน ข้อเสนอเพิ่ม: ใส่ rate limit
2. **มุมมองรายวิชา:** `GET /api/versions/{v}/classes` ตอนนี้รองรับ `view=group|teacher|room` ขอเพิ่ม `view=subject`
3. **ส่งออก PDF/Excel:** หน้าเว็บสร้างไฟล์เองจากมุมมองตารางดิจิทัล จึงไม่ต้องทำ `POST /api/versions/{v}/export` และ `GET /api/me/timetable/export` (ตอบ api.md §11 ข้อ "ส่งออก PDF ทำที่ไหน" ว่าเบราว์เซอร์) ยังต้องมี `GET /api/versions/{v}/print/{view}/{id}` สำหรับข้อมูลพรีวิว
4. **หลังตัดสินใจ 1.1:** ปรับ api.md ให้ตรงกับ [GLOSSARY.md](GLOSSARY.md) และข้อ 2.1–2.5 ข้างบน

## 4. ฝั่งหน้าเว็บตัดสินแล้ว (แจ้งให้ทราบ)

- หน้าเว็บเขียนด้วย TypeScript สร้าง type จาก `/openapi.json` ของอานนท์ โดย Pydantic model เป็นแหล่งจริง ไฟล์ api.md ปรับตาม
- ระหว่างรอ หน้าเว็บใช้ mock ที่รูปเดียวกับ api.md
- กริดตาราง: แถว = วัน คอลัมน์ = คาบ ป้ายภาคเรียนแสดงเป็น พ.ศ. ("1/2570")
- ข้อความหน้าจอสลับตามประเภทสถานศึกษา (อาชีวะ: แผนกวิชา · ครู) ชื่อในโค้ดและ API คง `department`, `teacher`
- หน้าก่อนล็อกอินมีการ์ด 3 ประเภทสถานศึกษาเป็นการแสดงแผนงาน ไม่เรียก API
- ข้อมูลตัวอย่างช่วงแรกมีภาควิชาเดียว ตัวสลับภาควิชาแสดงเมื่อมี membership มากกว่า 1
- ติดตั้งบน VM เดียวด้วย `docker compose` ชุดเดียวกัน หน้าเว็บ API และฐานข้อมูลอยู่โดเมนเดียวกันผ่าน reverse proxy
- หน้าตรวจผล OCR (design system §5.3) รวมเป็นหน้าเดียวกับขั้น 2
- หลักสูตรเข้าระบบด้วยการอัปโหลด PDF แล้ว OCR ส่วนอาจารย์ ห้อง และเวลาว่างกรอกผ่านฟอร์ม
- การเผยแพร่เป็นการกระทำที่หัวหน้าสั่งเองเท่านั้น ไม่มีสวิตช์เปิด/ปิดรวมของผู้ดูแลสถาบัน
