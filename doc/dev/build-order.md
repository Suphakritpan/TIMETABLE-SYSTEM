## เฟส 0 งานรากฐาน (ไม่ใช่หน้า)

1. ย้าย `src` ออกจาก `frontend/public/` สร้างไฟล์เริ่มต้น (`main.tsx`) ตั้ง ESLint
2. `tokens.css` + base (สีหลัก `#1f5fae`, สถานะ "ต้องแก้" เป็นส้ม)
3. AppShell: TopBar (ตัวสลับภาควิชา, กระดิ่ง), Nav, CommandToolbar, StatusBar, Stepper
4. คอมโพเนนต์พื้นฐาน: Button, Input, Badge, Tooltip, Toast, Dialog, InlineAlert, EmptyState, Skeleton, DataTable, Tabs
5. TimetableGrid แบบอ่าน (แถว = วัน, คอลัมน์ = คาบ, 7 สถานะ)
6. ชั้น API: client ที่มี type, mock ตาม api.md, ตัวเก็บเซสชัน, ตัวป้องกันเส้นทางตามบทบาท
7. พจนานุกรมข้อความตามประเภทสถานศึกษา (อาชีวะ: แผนกวิชา / ครู) และตัวแปลงปีเป็น พ.ศ. ("1/2570")

## ชั้น D ส่วนเสริมและขัดเกลา (นอก 31 หน้า)

1. หน้าตารางสาธารณะของนักเรียน (อ่านอย่างเดียว ไม่ล็อกอิน เฉพาะเวอร์ชันที่หัวหน้าเผยแพร่) ตาม [adr/0001](../adr/0001-public-read-only-timetable.md)
2. ส่งออก Excel + มุมมองรายวิชา
3. ผ่านรายการเข้าถึงได้ (design system §6.3) ภาษาอังกฤษ มุมมองมือถือแบบอ่านอย่างเดียวของ 4.2 และ 4.4
4. ทดสอบกับข้อมูลสังเคราะห์ขนาดใหญ่ (ตามโจทย์การแข่งขัน)
5. คู่มือผู้ใช้ และติดตั้งบน VM ด้วย compose ชุดเดียวกัน

## ทำไมเรียงอย่างนี้

- ขั้น 1 เลือกภาคเรียนจาก 3.4 และขั้น 5–7 ใช้อาจารย์/ห้องจาก 2.3 ในชั้น A ใช้ข้อมูลตัวอย่าง (seed) แทน แล้วหน้าจริงมาแทนในชั้น B/C
- หน้าที่ฝั่งหัวหน้าและฝั่งอาจารย์ใช้ข้อมูลร่วมกัน (ขั้น 3 กับ 4.2, ขั้น 4 กับ 4.3, ขั้น 8 กับ 4.5) สร้างเป็นคู่เพื่อทดสอบทั้งสองฝั่งพร้อมกัน
- 2.4.1 ต้องมี 3.5 รองรับ จึงอยู่ด้วยกัน และอยู่ท้ายเพราะ PDF อาชีวะที่รู้จักเป็นทางหลักอยู่แล้ว
- ขั้น 6 เป็นหน้ายากที่สุด (กริด ถาด ปักหมุด ตรวจสด) แยกส่งเป็น 3 รอบเพื่อให้ได้ของใช้ได้ก่อน
