# 1 ผู้ใช้และเป้าหมาย

ระบบจัดตารางเรียนอัตโนมัติ · ขั้นที่ 1 ของกระบวนการออกแบบเว็บ · เวอร์ชัน 2026-10-24

> **ไฟล์ที่เกี่ยวข้อง:** `tech-stack-list.txt` (สเปกฉบับเต็ม หัวข้อ USERS AND GOALS เป็นต้นทางของหน้านี้) · `users-goals-map.png` (แผนภาพ ผู้ใช้ → เป้าหมาย → เทคโนโลยี)

## สรุปใน 30 วินาที

- ระบบเดียวสำหรับทุกภาควิชา ติดตั้งเองบนเซิร์ฟเวอร์ของสถาบัน (self-hosted + โอเพนซอร์ส)
- ผู้ใช้คือ **บุคลากรของสถาบันเท่านั้น** นักศึกษา **ไม่ต้องล็อกอินเด็ดขาด** ได้รับแค่ตารางที่เผยแพร่แล้ว (พิมพ์ / ไฟล์)
- ผู้ใช้หลักคือ **หัวหน้าภาควิชา** เป้าหมายคือลดเวลาทำตารางจาก 3 วัน-1 สัปดาห์ ให้เหลือไม่เกิน 30 นาที

## วิสัยทัศน์

ระบบเดียวสำหรับทุกภาควิชา ยืดหยุ่นพอสำหรับสถาบันทั่วประเทศ (ผลิตภัณฑ์สุดท้าย) สร้างเดโมในเครื่องก่อน

**ติดตั้งเองบนเซิร์ฟเวอร์ (2026-10-24):** แต่ละสถาบันติดตั้งสำเนาของตนเองบนเซิร์ฟเวอร์ของตนเอง

## ปัญหาในปัจจุบัน

| ปัญหา | รายละเอียด |
|---|---|
| ทำด้วยมือ | ตารางเรียนทำใน Excel และบนกระดาษ ไม่มีอะไรอัตโนมัติ |
| ใช้เวลานาน | 3 วันถึง 1 สัปดาห์ต่อภาคเรียน |
| เวลาหมดไปกับการคุยกัน | ใครสอนได้เมื่อไหร่ ใครสอนวิชาไหน |
| เปลี่ยนไม่รู้จบ | การเปลี่ยนแปลงยังเข้ามาแม้ทำตาราง "สุดท้าย" เสร็จแล้ว |

## ผู้ใช้

| ผู้ใช้ | ทำอะไร | ใช้หน้าไหน | บัญชี |
|---|---|---|---|
| **หัวหน้าภาควิชา** (ผู้ใช้หลัก) | สร้างตารางของชั้นปีที่เลือกภาคเรียนละครั้ง · เปิดรอบสอบถามเวลาว่าง · อนุมัติการเปลี่ยนแปลง · เผยแพร่และพิมพ์ | ทุกหน้าของเว็บแอป | ได้รับเชิญจากผู้ดูแลระบบของสถาบัน |
| **อาจารย์** | ระบุเวลาไม่ว่าง วิชาที่สอนได้/อยากสอน ชั่วโมงสูงสุดต่อวัน · ตรวจตารางตนเอง · ส่งคำขอเปลี่ยนแปลง | เวลาว่างของฉัน · ตารางของฉัน · คำขอของฉัน (**เห็นเฉพาะตารางของตนเอง**) | ได้รับเชิญจากหัวหน้าภาควิชา หนึ่งบัญชีสังกัดได้หลายภาควิชา |
| **ผู้ดูแลระบบสถาบัน** | สร้างภาควิชา · เชิญหัวหน้า · ป้อนห้องที่ใช้ร่วมกัน · ดูแลการติดตั้งของสถาบัน (อัปเดต สำรองข้อมูล ตั้งค่าอีเมล อนุมัติรูปแบบหลักสูตรใหม่) | หน้าผู้ดูแล (ภาควิชา, หัวหน้า, ห้องร่วม, รูปแบบ, ระบบ) | สร้างตอนติดตั้ง (หน้าตั้งค่าครั้งแรก) |
| **ภาควิชาอื่น** | ทำเหมือนหัวหน้าภาควิชา ในโปรไฟล์ของตนเอง | — | — |
| **นักศึกษา** (ไม่ใช่ผู้ใช้) | ได้ตารางที่เผยแพร่แล้วของกลุ่มตนเอง (พิมพ์ A4 / ไฟล์) | — | **ไม่มี ตลอดไป** |

> **ไม่มีผู้ดูแลแพลตฟอร์มกลาง** แต่ละสถาบันรันสำเนาของตนเอง ผู้ดูแลโอเพนซอร์สส่งมอบโค้ดและรูปแบบหลักสูตรที่ใช้ร่วมกัน แต่ **ไม่เคยเห็นข้อมูลของสถาบันใดเลย**

**ทำไมภาควิชาอื่นสำคัญ:** ใช้ห้อง (และอาจารย์บางคน) ร่วมกัน ตารางที่เผยแพร่แล้วของภาควิชาเหล่านั้นจะจองห้อง

## เป้าหมาย

### ของหัวหน้าภาควิชา

| รหัส | เป้าหมาย | รองรับโดย (เทคโนโลยี) |
|:-:|---|---|
| **G1** | ตารางไม่ชนกันทุกกลุ่ม | FET solver · pre-check · ตัวตรวจกฎของเราเอง (core lib) |
| **G2** | เร็วกว่า 3 วัน-1 สัปดาห์มาก | รอบสอบถามเวลาว่าง (web + project service) · FET < 1 วินาที · "คัดลอกจากภาคก่อน" · ตารางตัวเลือก N แบบ |
| **G3** | คุมได้เอง (ย้ายคาบ ปักหมุดคาบที่ตกลงแล้ว วิชาเลือก) | หน้าจัดตาราง (React + dnd-kit) · ตรวจสดตอนวาง (`POST /api/check`) · ปักหมุด + รันใหม่รอบหมุด (FET locks) · Schedule / Reserve วิชาเลือก |
| **G4** | เชื่อข้อมูลที่อ่านจาก PDF ได้ | import service (pdftotext + ตัวอ่านรูปแบบหลักสูตร) · หน้าตรวจสอบ (ตาราง + ผังกระบวนวิชา) · ทุกค่าลิงก์ไปหน้า PDF ต้นทาง |
| **G5** | พิมพ์ A4 ดูเป็นทางการ | พรีวิวพิมพ์ (web) · ฟอนต์ไทย (Noto Sans Thai / Sarabun) · ส่งออก PDF |
| **G6** | ใช้งานต่อในภาคถัดไป | storage (PostgreSQL) · profile manager · คัดลอกจากภาคก่อน |

### ของอาจารย์

| รหัส | เป้าหมาย | รองรับโดย |
|:-:|---|---|
| **T1** | เวลาไม่ว่างและความต้องการได้รับการเคารพ | ตารางเวลาว่าง · กฎอาจารย์ใน FET (ตอนนี้เป็น **CORE** ไม่ใช่ทำทีหลัง) |
| **T2** | รู้เมื่อมีการเปลี่ยนแปลงที่กระทบตน | สถานะตรวจทาน · คำขอเปลี่ยนแปลง · การแจ้งเตือน · ประวัติเวอร์ชัน |

### ของผู้ดูแลระบบสถาบัน

| รหัส | เป้าหมาย | รองรับโดย |
|:-:|---|---|
| **I1** | ภาควิชาไม่จองห้องร่วมซ้ำกัน | ห้องส่วนกลาง + การจองห้องจากตารางที่เผยแพร่แล้ว |

## ตัวชี้วัดความสำเร็จ

- ทั้งภาคเรียนจาก PDF ถึงพิมพ์ ใช้แรงงาน **ไม่เกิน 30 นาที** (เป้าแรก ตั้งใจให้เร็วที่สุดเท่าที่ทำได้)
- ตารางที่บันทึกไม่มีการชนแบบ hard เลย
- ทุกคาบถูกจัดลง หรือแสดงเป็นคาบที่ยังไม่ลง พร้อมเหตุผลและวิธีแก้ที่ใกล้ที่สุด
- ไม่ต้องแก้ไฟล์ด้วยมือ
- วัดภายในแอป: เวลาต่อขั้น · จำนวนครั้งที่ย้ายด้วยมือ · จำนวนครั้งที่รัน FET · คะแนนคุณภาพ (กฎ soft ที่รักษาได้ + คะแนน 1-5 จากหัวหน้า) ใช้เทียบภายหลังเพื่อหาจุดสมดุลระหว่างความเร็วกับคุณภาพ

## ระบบต้องไม่ทำสิ่งเหล่านี้เด็ดขาด

| รหัส | ห้าม | เทคโนโลยีรับประกันอย่างไร |
|:-:|---|---|
| **N1** | เปลี่ยนตารางโดยผู้ใช้ไม่ได้สั่ง | มีแต่ project service เท่านั้นที่เขียน · ทุกการเปลี่ยนแปลงถูกบันทึก · เก็บเวอร์ชันไว้ |
| **N2** | แสดงข้อมูลอาจารย์นอกสถาบัน | ล็อกอิน + บทบาท · แต่ละสถาบันรันระบบของตนเอง ข้อมูลไม่ออกจากเซิร์ฟเวอร์ (PostgreSQL ใน Docker) · เป็นไปตาม PDPA ของไทย |
| **N3** | ให้นักศึกษาเข้าระบบ | ไม่มีบทบาทนักศึกษา |

## อยู่นอกขอบเขต (ตอนนี้)

- นักศึกษาเลือกวิชาเลือกในระบบ (Reserve เก็บเวลาว่างไว้ให้)
- ตารางสอบ

## ส่วนที่เป็นของทั้งสองฝั่ง

ฟีเจอร์ที่ผู้ใช้ต้องการและต้องใช้ส่วนเทคโนโลยีเฉพาะ:

| ฟีเจอร์ | ผู้ใช้ | เทคโนโลยี |
|---|---|---|
| ล็อกอิน + บทบาท | บุคลากรทุกคน | บัญชีในตัว (เสนอ) · project service ตรวจบทบาท |
| รอบสอบถามเวลาว่าง | หัวหน้า + อาจารย์ | หน้าเว็บ + project service + กฎอาจารย์ใน FET |
| ตรวจสดตอนวาง | หัวหน้า | dnd-kit + `POST /api/check` + core lib checker |
| พรีวิวพิมพ์ (A4) | หัวหน้า → นักศึกษา | เลย์เอาต์พิมพ์บนเว็บ + ฟอนต์ไทย |
| เวอร์ชัน + บันทึกการเปลี่ยนแปลง | หัวหน้า + อาจารย์ | project service (ผู้เขียนเพียงหนึ่งเดียว) + storage |
| คัดลอกจากภาคก่อน | หัวหน้า | profile manager + storage |

## ช่องว่างที่พบระหว่างเขียนเอกสารนี้

> - เทคโนโลยียังไม่มีส่วน **AUTH (ล็อกอิน)** จำเป็นสำหรับ G2/T1/N2 ต้องเลือก
> - **การแจ้งเตือน** (อีเมล / ในแอป) ยังไม่อยู่ในเทคโนโลยี จำเป็นสำหรับ T2
