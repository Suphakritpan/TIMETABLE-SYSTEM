==============================================
เวอร์ชัน: 2026-10-24 (ขั้นที่ 1 ของกระบวนการออกแบบเว็บ: ผู้ใช้และเป้าหมาย)

  users-goals-map.svg / .png แผนภาพ: ผู้ใช้ -> เป้าหมาย -> เทคโนโลยี และส่วนที่เป็นของทั้งสองฝั่ง

--------------------------------------------------
วิสัยทัศน์
--------------------------------------------------
ระบบเดียวสำหรับทุกภาควิชา ยืดหยุ่นพอสำหรับสถาบันทั่วประเทศ (ผลิตภัณฑ์สุดท้าย)
สร้างเดโมในเครื่องก่อน ติดตั้งเองบนเซิร์ฟเวอร์ (SELF-HOSTED) + โอเพนซอร์ส (2026-10-24): แต่ละสถาบันติดตั้งสำเนาของตนเองบนเซิร์ฟเวอร์ของตนเอง

ผู้ใช้คือ: บุคลากรของสถาบันเท่านั้น
นักศึกษา "ไม่ต้องล็อกอินเด็ดขาด" - ได้รับเพียงตารางที่เผยแพร่แล้ว (พิมพ์ / ไฟล์)

--------------------------------------------------
ปัญหาในปัจจุบัน
--------------------------------------------------
- ตารางเรียนทำด้วยมือใน Excel และบนกระดาษ ไม่มีอะไรอัตโนมัติ
- ใช้เวลา 3 วันถึง 1 สัปดาห์ต่อภาคเรียน
- เวลาส่วนใหญ่หมดไปกับการที่อาจารย์คุยกันเอง: ใครสอนได้เมื่อไหร่ ใครสอนวิชาไหน
- การเปลี่ยนแปลงยังเข้ามาเรื่อย ๆ แม้ทำตาราง "สุดท้าย" เสร็จแล้ว

--------------------------------------------------
ผู้ใช้
--------------------------------------------------
หัวหน้าภาควิชา (ผู้ใช้หลัก)
  ทำอะไร   : สร้างตารางเรียนของชั้นปีที่เลือก ภาคเรียนละครั้ง; เปิดรอบสอบถามเวลาว่างของอาจารย์;
             อนุมัติการเปลี่ยนแปลง; เผยแพร่และพิมพ์
  ใช้      : ทุกหน้าของเว็บแอป
  บัญชี    : ได้รับเชิญจากผู้ดูแลระบบของสถาบัน

อาจารย์
  ทำอะไร   : ระบุเวลาที่ไม่ว่าง วิชาที่สอนได้ / อยากสอน ชั่วโมงสูงสุดต่อวัน;
             ตรวจตารางของตนเอง; ส่งคำขอเปลี่ยนแปลง
  ใช้      : เวลาว่างของฉัน | ตารางของฉัน | คำขอของฉัน (เห็นเฉพาะตารางของตนเองเท่านั้น)
  บัญชี    : ได้รับเชิญจากหัวหน้าภาควิชา; หนึ่งบัญชีสังกัดได้หลายภาควิชา

ผู้ดูแลระบบของสถาบัน
  ทำอะไร   : สร้างภาควิชา เชิญหัวหน้าภาควิชา ป้อนห้องที่ใช้ร่วมกันหลายภาควิชา
             และดูแลการติดตั้งของสถาบันเอง (self-hosted, 2026-10-24): อัปเดต สำรองข้อมูล
             ตั้งค่าอีเมล อนุมัติรูปแบบหลักสูตรใหม่
  ใช้      : หน้าผู้ดูแล (ภาควิชา, หัวหน้า, ห้องร่วม, รูปแบบ, ระบบ)
  บัญชี    : สร้างตอนติดตั้ง (หน้าตั้งค่าครั้งแรก)

(ไม่มีผู้ดูแลแพลตฟอร์มกลาง: แต่ละสถาบันรันสำเนาของตนเอง ผู้ดูแลโอเพนซอร์สส่งมอบโค้ดและ
 รูปแบบหลักสูตรที่ใช้ร่วมกัน แต่ไม่เคยเห็นข้อมูลของสถาบันใดเลย)

ภาควิชาอื่น
  ทำอะไร   : เหมือนหัวหน้าภาควิชา ในโปรไฟล์ของตนเอง
  ทำไมสำคัญ: ใช้ห้อง (และอาจารย์บางคน) ร่วมกัน - ตารางที่เผยแพร่ของภาควิชาเหล่านั้นจะจองห้อง

นักศึกษา (ไม่ใช่ผู้ใช้ของระบบ)
  ได้อะไร  : ตารางที่เผยแพร่แล้วของกลุ่มตนเอง (พิมพ์ A4 / ไฟล์)
  บัญชี    : ไม่มี ตลอดไป

--------------------------------------------------
เป้าหมาย (ของหัวหน้าภาควิชา)                  -> รองรับโดย (เทคโนโลยี)
--------------------------------------------------
G1 ตารางที่ไม่ชนกันสำหรับทุกกลุ่ม              -> FET solver, pre-check, ตัวตรวจกฎของเราเอง (core lib)
G2 เร็วกว่า 3 วัน - 1 สัปดาห์มาก               -> รอบสอบถามเวลาว่าง (web + project service), FET < 1 วินาที,
                                                 "คัดลอกจากภาคก่อน", ตารางตัวเลือก N แบบ
G3 คุมได้เอง                                   -> หน้าจัดตาราง (React + dnd-kit), ตรวจสดตอนวาง (POST /api/check),
   (ย้ายคาบ, ปักหมุดคาบที่ตกลงแล้ว, วิชาเลือก)    ปักหมุด + รันใหม่รอบหมุด (FET locks), Schedule / Reserve วิชาเลือก
G4 เชื่อข้อมูลที่อ่านจาก PDF ได้               -> import service (pdftotext + ตัวอ่านรูปแบบหลักสูตร),
                                                 หน้าตรวจสอบ (ตาราง + ผังกระบวนวิชา), ทุกค่าลิงก์ไปหน้า PDF ต้นทาง
G5 พิมพ์ A4 ดูเป็นทางการ                       -> พรีวิวพิมพ์ (web), ฟอนต์ไทย (Noto Sans Thai / Sarabun), ส่งออก PDF
G6 ใช้งานต่อในภาคถัดไป                         -> storage (PostgreSQL), profile manager, คัดลอกจากภาคก่อน

เป้าหมายของอาจารย์
T1 เวลาไม่ว่างและความต้องการได้รับการเคารพ     -> ตารางเวลาว่าง, กฎอาจารย์ใน FET (ตอนนี้เป็น CORE ไม่ใช่ทำทีหลัง)
T2 รู้เมื่อมีการเปลี่ยนแปลงที่กระทบตน           -> สถานะตรวจทาน, คำขอเปลี่ยนแปลง, การแจ้งเตือน, ประวัติเวอร์ชัน

เป้าหมายของผู้ดูแลระบบสถาบัน
I1 ภาควิชาไม่จองห้องร่วมซ้ำกัน                 -> ห้องส่วนกลาง + การจองห้องจากตารางที่เผยแพร่แล้ว

--------------------------------------------------
ตัวชี้วัดความสำเร็จ
--------------------------------------------------
- ทั้งภาคเรียนจาก PDF ถึงพิมพ์ ใช้แรงงานไม่เกิน 30 นาที (เป้าแรก; ตั้งใจให้เร็วที่สุดเท่าที่ทำได้)
- ตารางที่บันทึกไม่มีการชนแบบ hard เลย
- ทุกคาบถูกจัดลง หรือแสดงเป็นคาบที่ยังไม่ลง พร้อมเหตุผลและวิธีแก้ที่ใกล้ที่สุด
- ไม่ต้องแก้ไฟล์ด้วยมือ
- วัดภายในแอป: เวลาต่อขั้น, จำนวนครั้งที่ย้ายด้วยมือ, จำนวนครั้งที่รัน FET,
  คะแนนคุณภาพ (กฎ soft ที่รักษาได้ + คะแนน 1-5 จากหัวหน้า) -> ใช้เทียบภายหลังเพื่อหาจุดสมดุลระหว่างความเร็วกับคุณภาพ

--------------------------------------------------
ระบบต้องไม่ทำสิ่งเหล่านี้เด็ดขาด                -> เทคโนโลยีรับประกันอย่างไร
--------------------------------------------------
N1 เปลี่ยนตารางโดยผู้ใช้ไม่ได้สั่ง              -> มีแต่ project service เท่านั้นที่เขียน; ทุกการเปลี่ยนแปลงถูกบันทึก; เก็บเวอร์ชันไว้
N2 แสดงข้อมูลอาจารย์นอกสถาบัน                 -> ล็อกอิน + บทบาท; แต่ละสถาบันรันระบบของตนเอง ข้อมูลจึง
                                                 ไม่ออกจากเซิร์ฟเวอร์ (PostgreSQL ใน Docker); เป็นไปตาม PDPA ของไทย
N3 ให้นักศึกษาเข้าระบบ                         -> ไม่มีบทบาทนักศึกษา

--------------------------------------------------
อยู่นอกขอบเขต (ตอนนี้)
--------------------------------------------------
- นักศึกษาเลือกวิชาเลือกในระบบ (Reserve เก็บเวลาว่างไว้ให้)
- ตารางสอบ

--------------------------------------------------
ส่วนที่เป็นของทั้งสองฝั่ง (ผู้ใช้และเป้าหมาย & เทคโนโลยี)
--------------------------------------------------
ฟีเจอร์ที่ผู้ใช้ต้องการและต้องใช้ส่วนเทคโนโลยีเฉพาะ:
  ล็อกอิน + บทบาท          ผู้ใช้: บุคลากรทุกคน   เทคโนโลยี: บัญชีในตัว (เสนอ), project service ตรวจบทบาท
  รอบสอบถามเวลาว่าง         ผู้ใช้: หัวหน้า + อาจารย์  เทคโนโลยี: หน้าเว็บ + project service + กฎอาจารย์ใน FET
  ตรวจสดตอนวาง             ผู้ใช้: หัวหน้า         เทคโนโลยี: dnd-kit + POST /api/check + core lib checker
  พรีวิวพิมพ์ (A4)          ผู้ใช้: หัวหน้า -> นักศึกษา  เทคโนโลยี: เลย์เอาต์พิมพ์บนเว็บ + ฟอนต์ไทย
  เวอร์ชัน + บันทึกการเปลี่ยนแปลง  ผู้ใช้: หัวหน้า + อาจารย์  เทคโนโลยี: project service (ผู้เขียนเพียงหนึ่งเดียว) + storage
  คัดลอกจากภาคก่อน         ผู้ใช้: หัวหน้า         เทคโนโลยี: profile manager + storage

--------------------------------------------------
ช่องว่างที่พบระหว่างเขียนเอกสารนี้
--------------------------------------------------
- เทคโนโลยียังไม่มีส่วน AUTH (ล็อกอิน) - จำเป็นสำหรับ G2/T1/N2 ต้องเลือก
- การแจ้งเตือน (อีเมล / ในแอป) ยังไม่อยู่ในเทคโนโลยี - จำเป็นสำหรับ T2
