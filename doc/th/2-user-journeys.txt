เส้นทาง A - หัวหน้าภาควิชา (หนึ่งภาคเรียน)

A1 เข้าใช้งาน
   ทำ      เปิดอีเมลเชิญจากผู้ดูแลระบบสถาบัน ตั้งรหัสผ่าน ล็อกอิน
   เห็น    หน้าล็อกอิน -> หน้าแรก
   รู้สึก  "ยากไหมนะกว่าจะใช้เป็น?"
   เสี่ยง  ยอมแพ้ถ้าหน้าแรกสับสน
   เราทำ   หน้าแรกมีปุ่มใหญ่ปุ่มเดียว: "เริ่มตารางเรียนภาคนี้"; แนะนำ 3 ขั้นในครั้งแรก
   สถานะ  OK (ผู้ใช้, 2026-10-24)

A2 ตัวจัดการโปรไฟล์
   ทำ      เปิดโปรไฟล์ภาคก่อน หรือสร้างใหม่
   เห็น    รายการโปรไฟล์ล่าสุด (ชื่อ, รูปแบบหลักสูตร, ภาคเรียน, สถานะ: ร่าง / ตรวจทาน / เผยแพร่)
   รู้สึก  "ไม่อยากพิมพ์ทุกอย่างใหม่"
   เสี่ยง  ต้องป้อนอาจารย์และห้องใหม่ทุกภาค
   เราทำ   "คัดลอกจากภาคก่อน" เก็บอาจารย์ ห้อง กฎไว้ มีแต่ PDF/ภาคเรียนที่เปลี่ยน
   สถานะ  OK - พอใช้ในตอนนี้

A3 สร้างโปรไฟล์ + ตั้งค่าพื้นฐาน   (แก้ 2026-10-24: ผู้ใช้ไม่ต้องเลือกรูปแบบจากรายการสำเร็จรูปอีกต่อไป)
   ทำ      ตั้งชื่อ เลือกภาคเรียน; อัปโหลด PDF หลักสูตรทันที;
           เพิ่มอาจารย์และห้องตอนนี้หรือทีหลังก็ได้ (ต้องมี "จำนวน" ห้องก่อนจัดตาราง)
   เห็น    ฟอร์มสั้น (ชื่อ, ภาคเรียน) -> อัปโหลด -> การ์ด "สิ่งที่เราพบ":
           รูปแบบ, เวอร์ชันหลักสูตร, ชั้นปี + ภาคเรียนที่พบ, รูปแบบหน่วยกิต, จำนวนสัปดาห์ต่อภาค - แต่ละค่ามีหน้า PDF ที่มา
   รู้สึก  "รูปแบบไหนคือของฉัน?" -> ตอนนี้: "สิ่งที่มันพบถูกไหม?"
   เสี่ยง  เลือกรูปแบบผิด = ตั้งค่าผิดทั้งหมดต่อจากนั้น; หลักสูตรชนิดใหม่ที่ระบบยังไม่รู้จัก
   เราทำ   ตรวจจับก่อน ยืนยันทีหลัง: ระบบอ่าน PDF แล้วเติมค่าตั้งให้ ผู้ใช้แค่ยืนยันหรือแก้
           แต่ละค่าแสดงหลักฐาน (หน้า + ข้อความที่จับคู่) จึงเห็นค่าผิดได้ง่าย
           เลย์เอาต์ที่ไม่รู้จัก -> ไม่เดาเงียบ ๆ -> ตั้งค่าแบบนำทาง: ผู้ใช้ชี้ที่หน้าตัวอย่าง
             (คอลัมน์ไหนคือรหัส / ชื่อ / หน่วยกิต / ชั่วโมง) แล้วบันทึกเป็น FORMAT DEFINITION ใหม่
           FORMAT DEFINITION = ข้อมูล (ไฟล์ตั้งค่า) ไม่ใช่โค้ด: หลักสูตรที่เปลี่ยนแค่เลย์เอาต์
             ไม่ต้องใช้โปรแกรมเมอร์และไม่ต้องอัปเดตระบบ มีแต่ระบบหน่วยกิตใหม่จริง ๆ ที่ต้องเขียนโค้ดใหม่
           รูปแบบใหม่เริ่มเป็น "ยังไม่ตรวจสอบ" (unverified) จนกว่าผู้ดูแลจะตรวจ จากนั้นสถาบันอื่นจึงใช้ได้

A4 อัปโหลด PDF + ตรวจข้อมูล
   ทำ      อัปโหลด PDF หลักสูตร ตรวจวิชาในตารางและผังกระบวนวิชา แก้แถวสีแดง
   เห็น    หน้าตรวจสอบ (ตาราง | ผังกระบวนวิชา) แถวที่ผิดเป็นสีแดงพร้อมเหตุผล
   รู้สึก  "มันอ่าน PDF ของฉันถูกไหม?"
   เสี่ยง  เชื่อชั่วโมงหรือหน่วยกิตที่ผิด; ไม่ตรงกับรูปแบบที่เลือก
   เราทำ   ทุกค่าลิงก์ไปหน้า PDF; เตือนเมื่อไม่ตรง; ไปต่อไม่ได้ตราบที่ยังมีแถวสีแดง
           ตรวจเร็ว (ผู้ใช้, 2026-10-24): คลิกค่าใดก็ได้ -> PDF เปิดข้างตารางที่หน้านั้น
             พร้อมไฮไลต์ตำแหน่งที่แน่นอน; ปุ่ม "แถวแดงถัดไป" กระโดดไปทีละจุดที่ผิด

A5 รอบสอบถามเวลาว่าง
   ทำ      เชิญอาจารย์ที่ยังไม่เข้าระบบ เปิดรอบพร้อมกำหนดส่ง ดูว่าใครส่งแล้ว
   เห็น    กระดานสถานะ (ส่งแล้ว / ยังไม่ส่ง / ล่าช้า) ปุ่มเตือน
   รู้สึก  "การตามคนคือส่วนที่ช้าที่สุด"
   เสี่ยง  อาจารย์พลาดกำหนดส่ง
   เราทำ   เตือนอัตโนมัติ; หลังกำหนด หัวหน้ากรอกแทนคนที่ขาด หรือทำเครื่องหมาย "ว่างได้ทุกเวลา"
   สถานะ  OK

A6 แก้ปัญหาจากข้อมูลอาจารย์
   ทำ      แก้รายการที่ถูกติดธง: วิชาที่ไม่มีใครสอนได้ อาจารย์สองคนอยากสอนวิชาเดียว อาจารย์ภาระเกิน
   เห็น    เช็กลิสต์ปัญหา แต่ละข้อมีเธรดความเห็น
   รู้สึก  "เมื่อก่อนต้องคุยกันเป็นวัน"
   เสี่ยง  อภิปรายไม่จบ
   เราทำ   ระบบสร้างรายการปัญหาเองจากสิ่งที่อาจารย์ส่ง (ไม่ต้องมีใครคอยสังเกต)
           รายการมีสองชนิด:
             BLOCKER  จัดตารางไม่ได้จนกว่าจะแก้
                      - วิชาที่ไม่มีอาจารย์สอนได้  -> หัวหน้ามอบหมายอาจารย์ (หรือทำเครื่องหมาย "อาจารย์ภายนอก / ต้องจ้าง")
                      - อาจารย์สองคนอยากสอนวิชาเดียว -> หัวหน้าเลือกคนเดียว หรือแบ่งกลุ่มให้ทั้งสอง
             WARNING  รันได้ แต่บางคนอาจไม่พอใจ
                      - วิชาของอาจารย์ใช้ชั่วโมงมากกว่าเวลาว่าง -> หัวหน้าแก้ หรือ "ยอมรับ" พร้อมบันทึกหมายเหตุ
           แต่ละรายการมีเธรดความเห็น; ปิดได้เมื่อมีการตัดสินใจเท่านั้น และบันทึกไว้ (ใคร เมื่อไหร่ ทำไม)
           จะไปต่อได้เมื่อ: ไม่มี blocker ค้าง และทุก warning ถูกแก้หรือยอมรับ ("รายการต้องว่าง" = ไม่มีอะไรที่ยังไม่ตัดสินใจ)

A7 กฎ + วิชาเลือก
   ทำ      ตรวจตารางเวลา กลุ่ม จำนวนห้อง วิชาเลือก (Schedule / Reserve) น้ำหนักกฎ
   เห็น    หน้ากฎ; กฎ hard เป็นสีเทา (มาจากหลักสูตร) กฎ soft มีระดับน้ำหนัก
   รู้สึก  "กฎพวกนี้หมายความว่าอะไร?"
   เสี่ยง  ทำทุกอย่างเป็น hard -> จัดไม่ลง
   เราทำ   ชื่อกฎเป็นภาษาง่าย ๆ ค่าเริ่มต้นของโปรไฟล์ pre-check อธิบายกรณีที่เป็นไปไม่ได้ก่อนรัน
           รายงาน PRE-CHECK (ผู้ใช้, 2026-10-24): หลังตรวจ จะมีรายงานสั้น (OK / ปัญหา / กฎเสี่ยง)
             ที่หัวหน้าต้อง ACKNOWLEDGE (รับทราบ) ก่อนปุ่ม Generate จะปลดล็อก; การรับทราบถูกบันทึกไว้กับการรัน

A8 สร้าง + จัดตาราง
   ทำ      กด Generate เทียบตัวเลือกที่ดีที่สุด ลากคาบ ปักหมุดคาบที่ตกลงแล้ว
   เห็น    ตารางเรียน ถาดคาบที่ยังไม่ลง ช่องสีแดงพร้อมเหตุผล คะแนนคุณภาพ
   รู้สึก  "เชื่อได้ไหม? แก้เองได้ไหม?"
   เสี่ยง  ผลที่ไม่ครบรู้สึกเหมือนล้มเหลว
   เราทำ   ผลบางส่วน + ถาด + เหตุผล + วิธีแก้ที่ใกล้ที่สุด; ตรวจสดทุกครั้งที่วาง; รันใหม่รอบหมุด
   สถานะ  OK

A9 ห้อง + อาจารย์ + พรีวิว
   ทำ      ยืนยันห้อง (FET เลือก) ยืนยันอาจารย์ของแต่ละคาบ ตรวจพรีวิว A4
   เห็น    หน้ามอบหมายพร้อมพรีวิว A4 สดด้านล่าง
   รู้สึก  "หน้าตาเหมือนกระดาษจริงไหม?"
   เสี่ยง  พบการชนช้าเกินไป
   เราทำ   แสดงการชนที่คาบนั้นตรง ๆ; พรีวิวเหมือนงานพิมพ์ทุกประการ
   สถานะ  OK

A10 ให้อาจารย์ตรวจทาน
   ทำ      ส่งร่างเข้าสถานะ REVIEW อ่านคำขอเปลี่ยนแปลง
   เห็น    รายการคำขอเปลี่ยน: ใคร อะไร เหตุผล ผลกระทบ (อะไรจะต้องย้าย)
   รู้สึก  "แก้อย่างหนึ่งพังอีกอย่างเสมอ"
   เสี่ยง  เปลี่ยนอย่างเดียวทำให้ทั้งตารางสับใหม่
   เราทำ   รันใหม่แบบเปลี่ยนน้อยที่สุด (อย่างอื่นปักหมุด); อนุมัติ / ปฏิเสธพร้อมหมายเหตุ
           คุยกันตัวต่อตัว (ผู้ใช้, 2026-10-24): หัวหน้ากับอาจารย์มักตกลงเรื่องเล็ก ๆ กันต่อหน้า
             หัวหน้าไม่ควรต้องยื่นคำขอหรือไล่ดูทั้งรายการสำหรับเรื่องนี้:
             DIRECT EDIT - ในสถานะ REVIEW หัวหน้าย้ายคาบ / สลับอาจารย์ได้ตรง ๆ บนตาราง;
               ตรวจสดและดูตัวอย่างผลกระทบเหมือนเดิม ("นี่จะย้ายอีก 2 คาบ") มีช่องเดียว: "ตกลงกับ ___" (ไม่บังคับ)
             บันทึกเป็นการเปลี่ยนแปลงเหมือนอื่น และแจ้งอาจารย์ที่ได้รับผลกระทบพร้อมหมายเหตุ
             การแก้เล็ก ๆ ที่ไม่กระทบอย่างอื่นมีผลทันที; การแก้ที่ย้ายคาบอื่นจะถามก่อนว่า "ใช้เลยไหม?"
             คำขอแบบเป็นทางการสำหรับอาจารย์ที่ไม่ได้คุยกับหัวหน้า หรือการเปลี่ยนใหญ่

A11 เผยแพร่ + พิมพ์
   ทำ      เผยแพร่ พิมพ์ / ดาวน์โหลดแยกตามกลุ่ม (และตามอาจารย์ ตามห้อง)
   เห็น    หน้าสรุป: ผลทั้งหมด หมายเลขเวอร์ชัน + วันที่
   รู้สึก  "เสร็จแล้ว - และพิสูจน์ได้ว่าไม่ชน"
   เราทำ   ล็อกเวอร์ชัน บันทึกการเปลี่ยนแปลง นักศึกษาได้รับสำเนาพิมพ์ (ไม่ต้องล็อกอิน)
   สถานะ  OK

A12 หลังเผยแพร่ (เมื่อไหร่ก็ได้ในภาคเรียน)
   ทำ      จัดการคำขอเปลี่ยนที่มาทีหลัง -> เวอร์ชันใหม่
   เราทำ   ตรวจผลกระทบเหมือนเดิม + เปลี่ยนน้อยที่สุด; แจ้งอาจารย์ที่ได้รับผลกระทบ; เก็บเวอร์ชันเก่าไว้
           direct edit (ดู A10) ใช้ได้เช่นกัน แต่สร้างเวอร์ชันใหม่เสมอ
   สถานะ  OK

เส้นทาง B - อาจารย์

B1 ได้รับเชิญ    เปิดลิงก์เชิญ ตั้งรหัสผ่าน (หรือเข้าด้วยบัญชีเดิมถ้าอยู่ภาควิชาอื่นแล้ว)
B2 ส่งข้อมูล     กรอกตารางไม่ว่างรายสัปดาห์ จัดอันดับวิชาที่สอนได้ ชั่วโมงสูงสุดต่อวัน; แก้ได้จนถึงกำหนดส่ง
                 รู้สึก "ความต้องการของฉันจะถูกเคารพไหม?" -> เราทำ แสดงใบรับ "ส่งแล้ว" + สิ่งที่หัวหน้าจะเห็น
B3 หารือ         ได้รับความเห็นในรายการที่ติดธง (เช่น สองคนอยากสอนวิชาเดียว) ตอบในระบบ
B4 ตรวจทาน       เห็นเฉพาะตารางของตนเองในสถานะ REVIEW; ส่งคำขอเปลี่ยนพร้อมเหตุผลถ้าจำเป็น
                 รู้สึก "ขอไปจะคุ้มไหม?" -> เราทำ แสดงสถานะคำขอ (รอ / อนุมัติ / ปฏิเสธ + หมายเหตุ)
                 ถ้าตกลงกันต่อหน้าแล้ว ไม่ต้องยื่นอะไร: จะได้รับแจ้ง "แก้โดย <หัวหน้า>: <หมายเหตุ>"
                 พร้อมช่องเวลาเก่า/ใหม่เทียบกันข้าง ๆ เพื่อดูว่าตรงกับที่ตกลง
B5 สุดท้าย       ได้รับแจ้งเมื่อเผยแพร่และเมื่อมีการเปลี่ยนแปลงภายหลัง; ดาวน์โหลด / พิมพ์ตารางของตนเอง
B2 ยังแสดงรายการ blocker/warning ที่เกี่ยวกับตนเอง (จาก A6) เพื่อให้รู้ว่าหัวหน้ากำลังตัดสินใจอะไร
สถานะ ทุกขั้นของ B OK (ผู้ใช้, 2026-10-24)

เส้นทาง C - ผู้ดูแลระบบสถาบัน (ครั้งเดียว แล้วนาน ๆ ครั้ง)
C1 ได้รับบัญชีสถาบันจากผู้ดูแลแพลตฟอร์ม
C2 สร้างภาควิชา เชิญหัวหน้าภาควิชา ป้อนห้องที่ใช้ร่วม (ใช้โดยหลายภาควิชา)
C3 ภายหลัง: เพิ่ม/ลบหัวหน้า ดูว่าภาควิชาไหนเผยแพร่แล้ว
สถานะ ทุกขั้นของ C OK

ทำไมไม่แยกเป็น 5 โปรไฟล์:
  - อาจารย์และห้องชุดเดียวกันรองรับทุกชั้นปีในเวลาเดียวกัน โปรไฟล์ที่แยกจะคิดว่าอาจารย์ X ว่าง
    จึงพบการชนได้แค่ด้วยการตรวจข้ามโปรไฟล์ - ส่วนที่เปราะบางที่สุด
  - ตรวจทานครั้งเดียว เผยแพร่ครั้งเดียว เวอร์ชันเดียวทั้งภาควิชา แทนที่จะเป็น 5 อันที่อาจเพี้ยนจากกัน

วิธีให้การเปลี่ยนแปลงเล็กและปลอดภัย:
  - แต่ละ year plan มีแท็บและสถานะของตัวเอง (done / out of date); แก้ข้อมูลปี 2 ทำให้เฉพาะปี 2 เป็น out of date
  - รันใหม่ทำต่อชั้นปี: ปีอื่นถูกปักหมุด คาบของปีอื่นจึงย้ายไม่ได้
  - หนึ่ง year plan อ่านจากหลักสูตร "หนึ่งเวอร์ชัน" เท่านั้น วิชาจึงไม่ปนกันภายในชั้นปี
  - ผู้ใช้เลือกจัดแค่บางชั้นปีก่อน (Scope) แล้วเพิ่มที่เหลือทีหลังได้
  - "คัดลอกจากภาคก่อน" คัดลอกโปรไฟล์; แต่ละ year plan เลื่อนขึ้นไปพร้อมนักศึกษา
