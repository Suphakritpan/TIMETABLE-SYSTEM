# Design System: ระบบตารางเรียน (ขั้นตอนที่ 7)

แนวทาง: เครื่องมือทำงานแบบ Office (Word/Excel) ไม่ใช่ Dashboard. ตารางเป็นพระเอก, UI ที่เหลือเป็นแถบเครื่องมือรอบตาราง.
อ้างอิง: sitemap (3), flows (4), wireframe (5), ER (6) และภาพ "ตรวจทานตารางที่สกัดได้" (split view + แผงแก้ช่อง).
ค่าจริงทั้งหมดอยู่ใน [tokens.css](tokens.css) ไฟล์นี้อธิบายเหตุผลและกติกา.

---

## 1. หลักการ + ทิศทางภาพ

| หลักการ | แปลงเป็นกติกา | เหตุผล |
|---|---|---|
| Familiarity | โครง 5 ส่วน (Top bar / Nav / Toolbar / Workspace / Status bar), ปุ่ม Save/Undo/Export ตำแหน่งเดิมทุกหน้า | หัวหน้าภาคใช้ Word/Excel ทุกวัน ไม่ต้องเรียนรู้ใหม่ |
| Simplicity | ไม่มีเงาหนัก ไม่ซ้อนการ์ด ไม่ใช้ gradient; แยกพื้นที่ด้วยเส้น 1px | ลดสิ่งรบกวน ให้สายตาอยู่ที่ตาราง |
| Information density | แถวตาราง 32px (compact 28px), ฟอนต์ตาราง 13px | ตาราง 5 วัน × 10 คาบ × หลายกลุ่ม ต้องเห็นพร้อมกัน |
| Consistency | งานแบบเดียวกัน (ตรวจข้อมูล, รอบเวลาว่าง, รายการปัญหา) ใช้ DataTable + Toolbar ชุดเดียว | ลดโค้ดและลดความสับสนข้ามบทบาท |
| Function first | ทุกองค์ประกอบต้องตอบได้ว่า "ผู้ใช้ทำงานอะไรด้วยสิ่งนี้" ไม่ตอบได้ = ตัดทิ้ง | ตามข้อกำหนดโครงการ |
| Accessibility | สถานะ = สี + ไอคอน/ข้อความเสมอ; คีย์บอร์ดครบ; คอนทราสต์ ≥ 4.5:1 | ภาพต้นแบบใช้ "สี" อย่างเดียวบอกความมั่นใจ OCR (ดู §5) |

ไม่ทำ: เลียนแบบ Ribbon ของ Office เต็มรูป, กราฟตกแต่ง, การ์ดสถิติ, animation ยาว.

## 2. Tokens

ไฟล์: [tokens.css](tokens.css) (ธีมสว่างเป็นค่าเริ่มต้น + ธีมมืดตาม `prefers-color-scheme` และ `data-theme`, ตามรูปแบบเดียวกับ prototype.html).

### 2.1 สี

| Token | สว่าง | ใช้กับ |
|---|---|---|
| `--bg` | #f3f4f6 | พื้นพื้นที่ทำงาน |
| `--surface` / `--surface-2` | #fff / #f9fafb | แผง ตาราง เมนู / หัวตาราง แถบเครื่องมือ |
| `--border` / `--border-strong` | #d1d5db / #9ca3af | เส้นแบ่ง / ขอบช่องกรอก |
| `--text` / `--text-2` | #1f2937 / #4b5563 | ข้อความหลัก / รอง |
| `--primary` (+hover/active/bg) | #1f5fae | ปุ่มหลัก ลิงก์ รายการที่เลือก |
| `--success/warning/error/info` (+bg/bd) | เขียว/ส้ม/แดง/ฟ้า | **เฉพาะสถานะ** ห้ามใช้ตกแต่ง |

กฎ: ใช้ `var(--…)` เท่านั้น. ใน 1 หน้าจอ สีสถานะต้องมีความหมายตรงตาม §2.5 เท่านั้น.
คู่สี fg บน bg ของสถานะผ่าน 4.5:1 ทั้งธีมสว่างและมืด (ตรวจเมื่อเปลี่ยนค่า).

### 2.2 ตัวอักษร (Sarabun, สำรอง Noto Sans Thai)

| บทบาท | ขนาด | น้ำหนัก |
|---|---|---|
| Page title | 26px | 600 |
| Section title | 18px | 600 |
| Body / Button / Input | 14px | 400 / 600 (ปุ่ม) |
| Table | 13px | 400 (หัวคอลัมน์ 600) |
| Secondary / Caption | 12px | 400 |

line-height 1.5 เสมอ (สระบน-วรรณยุกต์ไทยไม่ถูกตัด). ตัวหนาเฉพาะ: หัวข้อ, หัวตาราง, รหัสวิชาในเซลล์, ข้อความ error. ตัวเลข/รหัสวิชา/เวลาใช้ `font-variant-numeric: tabular-nums`.

### 2.3 ระยะ
4 · 8 · 12 · 16 · 24 · 32 (`--s1…--s8`). ใน Toolbar/ตาราง ใช้ 4–8; ระหว่างส่วนของหน้า 16–24; ขอบ Workspace 16.

### 2.4 ขอบ มุม เงา
เส้น 1px; มุม 4px (ควบคุม/เซลล์), 6px (dialog/เมนู). เงาใช้เฉพาะของที่ลอย (dialog, dropdown, toast, tooltip). แผง/ตารางไม่มีเงา.

### 2.5 ความหมายของสีสถานะ (ตายตัว)

| สถานะ | สี | ไอคอน/ข้อความ | ใช้ที่ |
|---|---|---|---|
| สำเร็จ / เผยแพร่แล้ว / ยืนยันแล้ว | success | ✓ | Badge, Toast, ขั้นเสร็จ |
| ต้องระวัง / WARNING / ล้าสมัย | warning | ⚠ | รายการปัญหา, ขั้นล้าสมัย |
| ผิดพลาด / BLOCKER / ชน / แถวแดง | error | ✕ หรือ ⛔ | ตรวจข้อมูล, ชนห้อง/อาจารย์ |
| ข้อมูล / ร่าง / กำลังตรวจทาน | info | ⓘ | Badge ร่าง/ตรวจทาน, คำแนะนำ |
| ปัจจุบัน / เลือกอยู่ | primary | เส้นใต้/แถบซ้าย | ขั้นปัจจุบัน, แท็บ, แถวที่เลือก |

## 3. Layout

```
┌ Top bar 44px: ชื่อระบบ | ตัวสลับภาควิชา | ค้นหา | 🔔 | บัญชี ─────────────┐
├ Nav 220px ┬ Command toolbar 40px (คำสั่งของหน้านี้) ──────────────────────┤
│ (พับได้)  │ Stepper (เฉพาะพื้นที่ทำงานโปรไฟล์) + แท็บชั้นปี               │
│           │ Workspace (ตาราง/ฟอร์ม; เลื่อนในตัวเอง)                       │
├───────────┴ Status bar 24px: จำนวนรายการ · ผลประมวลผล · "บันทึกแล้ว 14:02"┤
```

- Top bar, Toolbar, Status bar ตรึงตำแหน่ง; Workspace เป็นที่เดียวที่เลื่อน (ไม่ให้ทั้งหน้าเลื่อนซ้อน).
- Nav ตามบทบาท (หัวหน้า / อาจารย์ / ผู้ดูแล) ตาม sitemap §2–4. กลุ่มไม่เกิน 7 รายการ.
- Stepper 9 ขั้น (sitemap 2.4) อยู่ใต้ Toolbar: สถานะ เสร็จ ✓ / ปัจจุบัน / ล้าสมัย ⚠ / ล็อก 🔒; ขั้นล็อกกดไม่ได้และมี Tooltip บอกว่าติดอะไร.
- แผงแบ่งแนวนอน (เช่น PDF | ตาราง ในหน้าตรวจข้อมูล) ลากปรับขนาดได้, ค่าเริ่มต้น 40/60, ต่ำสุด 280px.
- Breakpoint: ≥1280 เต็ม; 1024–1279 พับ Nav เป็นไอคอน; <1024 ไม่รองรับการแก้ตาราง (อ่าน/ดูตารางของฉัน/ตอบรอบเวลาว่างได้บนมือถือ). ระบบนี้ออกแบบเดสก์ท็อปก่อน.
- เนื้อหาฟอร์มกว้างสุด 640px (ยกเว้นตาราง).

## 4. Component inventory

สถานะที่ทุกคอมโพเนนต์ต้องมีเมื่อเกี่ยวข้อง: Default · Hover · Focus (outline 2px `--focus`) · Active · Disabled · Error. Disabled ต้องมีเหตุผลใน Tooltip ถ้าเกิดจากเงื่อนไขของระบบ (เช่น "ยังมีแถวแดง 3 แถว").

| Component | Variants | หมายเหตุ |
|---|---|---|
| Button | primary · secondary · tertiary(ข้อความ) · destructive · icon | สูง 32px. **1 หน้า/1 Toolbar มี primary ได้ 1 ปุ่ม**. destructive ต้องผ่าน ConfirmDialog |
| Input | text · search · select · number · date · time | label อยู่บนช่อง, helper 12px ใต้ช่อง, error = ขอบ error + ข้อความ + ไอคอน (ไม่ใช้สีอย่างเดียว). ใช้ `<input type=date/time>` ของเบราว์เซอร์ก่อน |
| DataTable | sort · filter · select · inline-edit · sticky header/col · row status | ดู §5. แถวสูง 32/28px |
| Tabs | หลักสูตร×ชั้นปี · ตาราง/ผังกระบวนวิชา | เส้นใต้ primary หนา 2px; ใช้ลูกศรซ้าย/ขวาเลื่อนแท็บ |
| Stepper | 9 ขั้น + 4 สถานะ | เฉพาะพื้นที่ทำงานโปรไฟล์ |
| Dialog | form · confirm | โฟกัสติดใน dialog, Esc ปิด, โฟกัสกลับปุ่มที่เปิด |
| ConfirmDialog | ปกติ · destructive | บอกผลกระทบเป็นข้อความ ("จะทำให้ขั้น 5–9 ของชั้นปี 2 ล้าสมัย") ปุ่มยืนยันใช้คำกริยาเฉพาะ ไม่ใช่ "ตกลง" |
| DropdownMenu | คำสั่งเพิ่มเติม · เมนูคลิกขวา | คีย์บอร์ด ↑↓ Enter Esc; ตัวคั่นกลุ่ม |
| Tooltip | ไอคอน/ปุ่ม disabled | หน่วง 400ms; ไม่ใส่ข้อมูลที่จำเป็นต่อการตัดสินใจ |
| Badge | success · warning · error · info · neutral | ไอคอน+ข้อความสั้น เช่น "✓ เผยแพร่แล้ว" "⚠ ล้าสมัย" "ร่าง" |
| Toast | success · info · error | มุมล่างขวา 4 วิ, error ค้างจนปิด; มี Undo เมื่อย้อนได้; `role=status` (error = `alert`) |
| EmptyState | — | 1 ประโยคอธิบายเหตุ + 1 ปุ่มคำสั่งถัดไป ("ยังไม่มีโปรไฟล์ — คัดลอกจากภาคก่อน") |
| LoadingState | skeleton แถวตาราง · progress บาร์ (ระบุ %/ขั้น) · spinner ในปุ่ม | งาน solver/OCR นาน: แสดงขั้นปัจจุบัน + ปุ่มยกเลิก |
| InlineAlert | info · warning · error | แถบในหน้า (ไม่ใช่ Toast) สำหรับ blocker ที่ต้องแก้ เช่น "ยังมีแถวแดง" |
| CommandToolbar | กลุ่มคำสั่ง + ตัวคั่น | ซ้าย: สร้าง/นำเข้า/ส่งออก; ขวา: primary ของหน้า |
| StatusBar | ข้อความ + ตัวนับ | `aria-live=polite` |
| SplitPane | แนวนอน | ลากด้วยเมาส์ + ปุ่มลูกศร |
| PageHeader | title + breadcrumb | ไม่ซ้ำกับ Toolbar |

ทำภายหลัง: DatePicker แบบปฏิทินเต็ม, Command palette, Ribbon, ตั้งค่าธีมสีเอง, ย้ายแถวด้วยลากในทุกตาราง.

## 5. ตารางสอน + ข้อมูลเชิงโครงสร้าง

### 5.1 TimetableGrid (หัวใจของระบบ)
- แถว = วัน (จันทร์–ศุกร์/เสาร์), คอลัมน์ = คาบ; หัวคอลัมน์แสดง **เลขคาบ + เวลา** (เช่น "7 · 14:00"). ตรึงหัวแถว (วัน) และหัวคอลัมน์ขณะเลื่อน.
- เส้นตารางบาง 1px `--border` ทุกเซลล์; ความกว้างคาบเท่ากัน; คาบต่อเนื่อง (2 คาบ) = เซลล์รวมกว้างเท่า 2 คาบ.
- เนื้อหาเซลล์ เรียงตามลำดับสแกน (บรรทัดเดียวต่อรายการ, ตัดด้วย `…` + Tooltip/แผงรายละเอียดเมื่อเลือก):
  1. **รหัสวิชา** (ตัวหนา)  2. ชื่อวิชา  3. ห้อง · ท-ป-น  4. ครู
- ความสูงเซลล์คงที่ ≥ 56px; ข้อความเกินตัดไม่ขึ้นบรรทัดใหม่เกิน 2 บรรทัด.

### 5.2 สถานะเซลล์ (สี + สัญลักษณ์ + ข้อความ)

| สถานะ | พื้นหลัง | ขอบ | สัญลักษณ์ที่มุมเซลล์ |
|---|---|---|---|
| ปกติ | `--surface` | solid | — |
| ว่าง | ลายเส้นทแยงจาง / พื้น `--surface-2` | solid | — |
| ยังไม่ได้จัด (อยู่ในถาด) | `--surface` | dashed | "ยังไม่ลง" |
| มีปัญหา: WARNING | `--warning-bg` | `--warning-bd` | ⚠ |
| ชน / BLOCKER | `--error-bg` | `--error-bd` 2px | ✕ + เซลล์คู่ชนไฮไลต์ |
| ปักหมุด | ปกติ | ปกติ | 📌 |
| เลือกอยู่ | `--primary-bg` | `--primary` 2px | — |

ชนต้องมีข้อความอธิบายใน Tooltip/แผงข้าง ("ชนกับ ป.31901-2001 · อ.ปฐพนพัทธ์ · จันทร์ คาบ 7").

### 5.3 หน้า "ตรวจทานตารางที่สกัดได้" (จากภาพต้นแบบ)
ภาพต้นแบบใช้ระดับความมั่นใจ OCR เป็น 4 สีฟ้า/ขาว + เส้นประ. ปรับดังนี้ เพื่อไม่พึ่งสีอย่างเดียวและไม่ใช้ฟ้าซ้ำกับสี "เลือก/ปัจจุบัน":

| ภาพต้นแบบ | ปรับเป็น |
|---|---|
| < 70% ต้องแก้ (ฟ้า) | `--warning-bg` + ⚠ + "58%" ในเซลล์ → นับใน "ต้องตรวจ" |
| 70–85% ควรดู (ขาวขอบเทา) | `--surface` + "ควรดู" ตัวเล็ก |
| > 85% ผ่าน | `--surface` ไม่มีเครื่องหมาย |
| ยืนยันแล้ว (น้ำเงินเข้ม) | `--success-bg` + ✓ |
| ถูกย้าย/ปรับด้วยมือ (เส้นประ) | เส้นประ + ไอคอน ✎ |
| เลือกอยู่ | `--primary-bg` + ขอบ primary 2px (เช่นเดิม) |

- คำอธิบายสี (legend) ต้องแสดงสัญลักษณ์เดียวกับในเซลล์ และเป็น Filter ได้ (กดเพื่อโชว์เฉพาะสถานะนั้น).
- ตัวนับ "ต้องตรวจ 17/17 ช่อง" อยู่ใน Toolbar; ปุ่ม "ช่องถัดไปที่ต้องตรวจ" = secondary, "ยืนยันและบันทึกเข้าฐานข้อมูล" = primary และ disabled (พร้อมเหตุผล) จนกว่าช่องที่ต้องตรวจจะเหลือ 0.
- แผงซ้าย (ภาพต้นฉบับ) ไฮไลต์กรอบตรงกับเซลล์ที่เลือกในตารางขวา และเลื่อน/ซูมตามอัตโนมัติ; ต้นฉบับไม่ถูกแก้ (ตาม ER: `og_file`).
- แผง "แก้ช่อง" (ภาพที่ 2): ฟอร์มใต้ตาราง/ลอยข้าง, ปุ่มเรียง **ยืนยันช่องนี้** (primary) · ข้ามไปช่องถัดไป (secondary) · คืนค่าเดิมจาก OCR (tertiary). ป้าย "· 96%" ข้าง label ให้คงไว้ทุกช่องที่มาจาก OCR; ช่องที่ความมั่นใจต่ำมีขอบ warning + ⚠. คีย์ลัด: Enter = ยืนยัน, Alt+→ = ถัดไป.
- ช่องตัวเลข ท/ป/น/ช: label ตัวย่อต้องมี Tooltip (เดิมมีบรรทัดอธิบายอยู่ ให้คงไว้).

### 5.4 DataTable ทั่วไป (ตรวจข้อมูลหลักสูตร, บุคลากร, รอบเวลาว่าง, รายการปัญหา, คำขอเปลี่ยน)
- หัวตรึง, คอลัมน์แรกตรึงเมื่อกว้างเกินจอ; เรียงด้วยคลิกหัวคอลัมน์ (ลูกศร ▲▼ + `aria-sort`).
- คอลัมน์สถานะอยู่ซ้ายสุดหรือขวาสุดเสมอ ใช้ Badge. ตัวเลขชิดขวา ข้อความชิดซ้าย.
- แถวแดง (ตรวจข้อมูล): ขอบซ้าย error 3px + ไอคอน ✕ + คำอธิบายในคอลัมน์ "ปัญหา"; ปุ่ม "แถวแดงถัดไป".
- inline edit: เฉพาะ ค่าที่ไม่กระทบแถวอื่นและย้อนกลับได้ (ชื่อ จำนวนที่นั่ง หมายเหตุ). ค่าที่กระทบกฎ/ตาราง (วิชา ครู คาบ) → เปิดแผงแก้ไข/Dialog.
- การเลือกหลายแถว: checkbox ซ้ายสุด + Shift-click ช่วง.

### 5.5 ตารางความพร้อมของอาจารย์ (เวลาว่างของฉัน)
กริด วัน×คาบ แบบเดียวกับ 5.1; เซลล์ "ไม่ว่าง" = `--error-bg` + ✕ (ไม่ใช่สีเดียว); ลากเลือกช่วงได้, คีย์บอร์ด Space สลับ. ไม่ว่างในภาควิชาอื่น = เส้นทแยง + ป้าย "ภาควิชาอื่น" (หัวหน้าเห็น, ตาม sitemap 3).

## 6. Interaction + Accessibility

### 6.1 Interaction
- คำสั่งอยู่ใกล้ข้อมูล: คำสั่งทั้งตาราง → Toolbar; คำสั่งของแถว/เซลล์ → คลิกขวาหรือปุ่ม ⋯ (เมนูเดียวกัน).
- ย้อนกลับได้ (เปลี่ยนสถานะ, ย้ายคาบ, ลบแถว) → ทำทันที + Toast "ย้อนกลับ" 8 วิ; Ctrl+Z ใช้ได้ในพื้นที่ทำงานตาราง.
- ย้อนกลับยาก (เผยแพร่, ลบภาควิชา, รัน Generate ทับผลเดิม, Direct edit หลังส่งตรวจทาน) → ConfirmDialog ที่บอกผลกระทบ. เผยแพร่: เฉพาะหัวหน้า; ผู้ช่วยเห็นปุ่ม disabled + เหตุผล.
- ลากย้ายคาบ: แสดงเซลล์ปลายทางที่วางได้/ชน ทันทีขณะลาก (✓/✕ + ข้อความ); วางที่ชน → ไม่ทำ + Toast อธิบาย. ต้องมีทางเลือกที่ไม่ใช้ลาก (แผงแก้ช่อง: เลือกวัน/คาบจาก select).
- Feedback เสมอหลัง บันทึก/นำเข้า/ส่งออก/ประมวลผล: StatusBar (ถาวร) + Toast (ชั่วคราว). การบันทึกอัตโนมัติแสดง "บันทึกแล้ว HH:mm".
- เคารพ "ขั้นล็อก/ล้าสมัย": แสดงเหตุผลและทางไปแก้ ไม่ซ่อนปุ่ม.
- Animation ≤ 100ms เฉพาะ hover/focus; ปิดทั้งหมดเมื่อ `prefers-reduced-motion`.
- ข้อความ UI: กริยานำ ภาษาไทยสั้น, ภาษาอังกฤษสลับได้ตามบัญชี (`user.language`); ห้าม hardcode ข้อความในคอมโพเนนต์ ใช้คีย์ i18n.

### 6.2 คีย์ลัดขั้นต่ำ
Ctrl+S บันทึก · Ctrl+Z/Y ย้อน/ทำซ้ำ · Ctrl+F ค้นหาในตาราง · ลูกศร เคลื่อนที่ในกริด · Enter แก้/ยืนยัน · Esc ยกเลิก/ปิด · F6 สลับพื้นที่ (Nav → Toolbar → Workspace → Status).

### 6.3 Accessibility (ตรวจก่อนปิดงานทุกหน้า)
- คอนทราสต์: ข้อความ ≥ 4.5:1, ขอบควบคุม/ไอคอน ≥ 3:1 (ทั้งสองธีม).
- ไม่พึ่งสี: ทุกสถานะมีไอคอนหรือข้อความ (ตาราง §2.5, §5.2).
- คีย์บอร์ด: Tab ครบทุกคำสั่ง, ลำดับ Tab = ลำดับสายตา, focus เห็นชัด, ไม่มี keyboard trap นอก dialog.
- ตาราง/กริด: `role=grid` สำหรับตารางที่แก้ไขได้, `role=table` สำหรับอ่านอย่างเดียว; หัวแถว/คอลัมน์ใช้ `scope`; เซลล์รวมคาบใช้ `colspan` + `aria-label` ("จันทร์ คาบ 7–8 …").
- ฟอร์ม: `label` ผูกทุกช่อง; error ผูกด้วย `aria-describedby`; สรุป error บนสุดเมื่อ submit ไม่ผ่าน.
- ขนาดเป้าหมายคลิก ≥ 24×24px (WCAG 2.2), ปุ่มหลัก 32px.
- ประกาศเปลี่ยนแปลง: Toast/StatusBar ใช้ live region.
- พิมพ์: หน้าตารางที่พิมพ์ (A4) ใช้ธีมสว่างขาวดำ; สถานะต้องอ่านได้เมื่อพิมพ์ขาวดำ (ใช้ไอคอน/เส้นประ).

## 7. โครงสร้างโค้ด Frontend

กติกา: **ข้อมูลแยกจากการแสดงผล** — คอมโพเนนต์ UI รับ props, ไม่เรียก API เอง; หน้า (feature) เป็นผู้ดึงข้อมูล.

```
src/
  styles/
    tokens.css            # ← th/7-design-system/tokens.css
    base.css              # reset + typography + print
  ui/                     # คอมโพเนนต์กลาง ไม่รู้จักโดเมน (Button, Input, DataTable, Tabs, Dialog, Menu, Tooltip, Badge, Toast, EmptyState, Loading, Alert)
    Button/ Button.tsx Button.module.css Button.test.tsx
  shell/                  # AppShell, TopBar, Nav, CommandToolbar, StatusBar, SplitPane, Stepper
  timetable/              # โดเมนตาราง: TimetableGrid, TimetableCell, CellStatus, ConflictTooltip, UnplacedTray
  features/               # หนึ่งโฟลเดอร์ต่อหน้า/ขั้นใน sitemap
    review-extract/       # หน้า split view + แผงแก้ช่อง
    availability/ issues/ rules/ generate/ publish/ ...
  api/                    # client + types (ตาม ER) แยกจาก UI
  i18n/ th.json en.json
```

- ไม่มี `ui/` → `features/` ย้อนกลับ (ทิศเดียว: features → timetable/shell → ui → styles).
- ชื่อสถานะโดเมน (`BLOCKER`, `WARNING`, `draft|review|published`, `not_started|done|out_of_date`) เป็น enum กลาง ตรงกับ ER; ตาราง map enum → Badge/CellStatus อยู่จุดเดียว ไม่กระจายตามหน้า.
- คอมโพเนนต์ใหม่เข้า `ui/` เมื่อใช้ ≥ 2 ที่ (rule of three ผ่อนเป็นสอง เพราะมีหลายบทบาทใช้หน้าซ้ำ).
- ทดสอบ: ทุก `ui/` มี test สถานะหลัก + ตรวจ a11y อัตโนมัติ (axe); `TimetableGrid` มี test สถานะเซลล์ทั้ง 7.

## 8. MVP vs. ภายหลัง

### MVP (ทำก่อน เรียงลำดับ)
1. `tokens.css` + base (ธีมสว่าง, ธีมมืดมีแล้วเพราะเป็นแค่ค่าตัวแปร)
2. AppShell: TopBar, Nav, CommandToolbar, StatusBar, Stepper
3. Button, Input(text/select/number/date/time), Badge, Tooltip, Toast, Dialog + ConfirmDialog, InlineAlert, EmptyState, LoadingState
4. DataTable (sort, เลือก, sticky header, สถานะแถว, inline edit แบบจำกัด) + Tabs
5. TimetableGrid (อ่าน + เลือกเซลล์ + 7 สถานะ + ตรึงหัว) + แผงแก้ช่อง
6. หน้าตรวจทานที่สกัดได้ (SplitPane + legend filter + ปุ่มช่องถัดไป)
7. Accessibility ผ่านรายการ §6.3 + i18n th/en + print A4 ของตาราง

### ภายหลัง
- ลากวางเต็มรูปแบบในตารางสอน (MVP: เลือกเซลล์ + แผงแก้ + ลากย้ายคาบแบบพื้นฐาน)
- DatePicker ปฏิทิน, Command palette, คีย์ลัดปรับแต่งได้
- Tabular density toggle (32/28px) ให้ผู้ใช้เลือก (MVP: ตายตัวต่อหน้า)
- ธีมสีสถาบัน / โลโก้ในตั้งค่า
- มุมมองมือถือสำหรับการแก้ตาราง
- Storybook / เอกสารคอมโพเนนต์แบบโต้ตอบ (MVP: ไฟล์นี้ + test)
- Realtime presence/ตัวชี้ผู้แก้พร้อมกัน

### ตัดสินใจที่ต้องการจากคุณ
- ยืนยันสีหลัก (#1f5fae น้ำเงิน) — เปลี่ยนที่ `--primary` จุดเดียว.
- ภาพต้นแบบใช้ฟ้าเป็นสี "ต้องแก้" (ความมั่นใจต่ำ) — ผมเปลี่ยนเป็นส้ม warning เพราะฟ้า = "เลือก/ปัจจุบัน" (§5.3). ถ้าต้องการคงสีเดิม บอกได้.
